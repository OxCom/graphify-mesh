# `--repo` sync: stage timing and the flag, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure every sync stage's wall and CPU time, then add `graphify-mesh-sync --repo <id>` so one repo can be refreshed without running `graphify` on the others.

**Architecture:** Timing extends the existing per-stage `rss.StageRssTracker.mark()` calls. `--repo` becomes a `Settings.only_repos` set. Inside the per-project loop, an unselected repo whose digest changed is treated like an unchanged one: its last graph joins the merge, and its state entry stays as it was. Every later stage runs unchanged over all repos.

**Tech Stack:** Python 3.11+, argparse, pytest in Docker (`graphify-mesh-test` image).

**Spec:** `docs/superpowers/specs/2026-11-19-repo-sync-design.md`

## Global Constraints

- Git is read-only for agents. The user commits. "Commit" steps below mean: stop and list the files for the user.
- `.py` files are edited only through Serena (`replace_content`, `replace_symbol_body`, `insert_*`), then `get_diagnostics_for_file`.
- Tests, ruff and mypy run in Docker: `docker run --rm -v "$PWD":/app graphify-mesh-test …`.
- Hard invariants 1–3 in `CLAUDE.md` stay untouched: no cross-repo structural edges, every generation rebuilt from empty, no `build_from_json`.
- Exit codes: unknown or disabled `--repo` id → 2, before the lock. Lock held → 3, as today (`cli.py`, `LockHeldError`).
- `--repo` grants no shrink, and never sets `producer_changed`.
- Live runs go through systemd only after the user approves reinstalling the wheel. No second sync process runs beside the timer. After the install, `graphifyy` must still be `0.9.112`.
- Out of scope: caches (steps 2–5), and `graphify/bin/graphify-sync-kick` wiring (knowledge-base-83 owns it).

## Review Focus

- `--repo` names a registered, enabled repo that reconcile then reports as `broken`. The registry check before the lock cannot see this. Expected: the run behaves as a full run does for a broken repo (its last graph is merged and its row is `broken_symlink`), every other repo is deferred, and the exit code stays 0. Test `test_selected_broken_repo_reported` in Task 3.
- `--repo a` where `a` itself is unchanged. Expected: skip as usual, publish, empty `pending_repos`. Test in Task 3.
- An unselected repo whose ignore rules changed, or whose `graph.json` drifted. Expected: not rebuilt, not forced, state kept, listed in `pending_repos`. Test in Task 3.
- `--repo` combined with `--dry-run`. Expected: only selected repos show `would_*`, others show `deferred`. Test in Task 3.
- An unselected repo with no `graph.json` yet (bootstrap pending). Expected: listed in `pending_repos`, absent from the merge, no shrink refusal. Test in Task 3.
